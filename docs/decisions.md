# 決まっていること

このリポジトリ（Retro Boy のラッパー）について、持ち主と開発に使った Claude のセッションで決めたことの一覧。2026-11-01 に、開発に使ったセッションのチェックリスト（決定事項）から書き移した。`#123` はそのカードの番号（あとで追えるように残す）。取り消された決定は書いていない。

仕組みの詳しい説明は [README](../README.md) と `docs/` のほかの文書。作業の手順は [dev-notes.md](dev-notes.md)。

## 土台

- **#1** 持ち主の設計書（`retro_boy_wrapper_design.md`。リポジトリの外）に沿って作る。文書に「設計書」「設計書 Step 7」とあるのはこれのこと。
- **#45** 本家 Retro Boy のコアを rev 固定で取得し、必要な書き換えはパッチで当てる。UI は自作。市販 ROM は git に入れず、自作テスト ROM は入れてよい。
  - `scripts/prepare-core.sh` が `core/upstream.rev` の本家を `core/upstream/` に取り、`core/patches/*.patch` を当てる。書き換えは通信ケーブルなど最小限。自作テスト ROM は `testroms/`（`.gitignore` の例外）。使い捨ての計測スクリプトは入れない。ライセンスは Apache-2.0。道具は brew の rustup・wasm-pack・rgbds（brew の Rust は消さない）。
  - 持ち主:「サブモジュールが悪いのでは？」「実際のゲームのROMをあげないのは、著作権としてアウトだからです。」
  - GitHub へのフォークなど、外に出る操作は持ち主に確かめる。
- **#52** 自作ゲームはこのリポジトリに同梱し、ROM ファイルとして配布せず、アプリに内蔵して配信する（外から ROM を渡さなくても選べる）。
  - 設計書 6 章「ROM を成果物や配信に含めない」は市販 ROM にだけ当てはめ、自作 ROM は例外。市販 ROM を dist に入れない検査は、内蔵用の置き場だけ例外にして残す。
  - いまは、ソースを別の非公開リポジトリで作り、できた ROM と攻略サイトだけをここに置くゲームもある（[builtin-games.md](builtin-games.md) の「ソースが別のリポジトリにあるゲーム」）。
- **#143** GB 版のテイマーズライフは内蔵ソフトから外す。いまの内蔵ソフトは [builtin-games.md](builtin-games.md) のとおり。

## 見た目と操作

- **#46** iPhone 縦持ちのゲームボーイカラー風（クリアパープル・配色 A clear）。ダーク基調で白い背景は使わない。スピーカー穴なし、SELECT/START は水平。アイコンは持ち主の画像。
  - 縦長の空きはそのまま（ボタンは親指の届く下）。ロゴ・商標は使わない。画面の余計なチカチカは出さず、ボタンの押した見た目だけ手応えとして残す。
  - 持ち主:「白は背景色になるべく使いたくない」「セレクトとスタートが斜めなのは気持ち悪いので水平に。」「画面の余計なチカチカをなくしてください」
- **#47** 方向はぷにコン。メニューで「両手／片手 A（寄せ配置）／片手 B（ジェスチャー）」を選べる（右手用）。片手 B のぷにコンは中心を固定。
  - 片手 B は なぞる＝方向、タップ＝A、長押しか 2 本目の指＝B。操作説明や目印は触るたびに変えない。
  - 持ち主:「片手Bで一度出現したぷにコンが動くのが嫌なので固定してほしい」
- **#154** 片手 B でも、A・B ボタンを画面の角（操作の部分の左下の空いた所）に押せるボタンとして置く。ジェスチャーは残す。ぷにコンの中心は固定のまま。
- **#119** GBA の画面は横幅を画面いっぱい使う（横の余白をなくす）。整数倍にこだわらず横幅に合わせて拡大し、縦横の比 3:2 は保つ。GB/GBC の画面は変えない。
- **#120** そのためのドットの太さの不そろいは気にならない。このままでよい。

## セーブ

- **#48** ゲーム内セーブは ROM ごとに localStorage へ 10 秒ごと＋閉じる直前に書く。画面のセーブ／ロードは ROM ごと 1 枠のメモリーセーブで、ロードは画像つきの確認を出す。
  - ゲーム内セーブのキーは ROM の SHA-256。`.rbs` の書き出し・読み込みはメニューに残し、読み込みも確認を出す。空の枠はロード不可。「セーブしました」は 1.5 秒。
- **#98** ゲーム内セーブだけの書き出しは作らない。引っ越しはメモリーセーブの書き出し（GB は `.rbs`、カートリッジの RAM も含む）で行う。
  - 持ち主:「メモリーセーブはゲーム内セーブも含んでる認識。」
  - [future-work.md](future-work.md) の「ゲーム内セーブのバックアップ」は、この決定（と #512）より前に書いたもの。
- **#512** GBA のメモリーセーブの書き出し（`.ss1`）にも、ゲーム内セーブ（フラッシュ）を入れる。読み込むときは「ゲーム内セーブも置き換えるか」を「いいえ」始まりで確かめる。
  - 前の `.ss1` は mGBA の `SAVESTATE_RTC` だけで、別のブラウザで読むと「つづきから」で進めなかった（`mgba/glue/mgba-glue.c`）。
- **#294** 内蔵ソフトはもう人が遊んでいるので、セーブデータの互換性は必須。公開中の版で作ったゲーム内セーブが、新しい版でそのまま続きから遊べること。形を変えるときは古い版→新しい版の読み替えを作る。
  - 持ち主:「ここから先はセーブデータの互換性は必須です」
- **#300** メモリーセーブ（セーブステート）が版をまたいで引き継がれないことの知らせは要らない（持ち主は理解した）。
  - #294 の本文はメモリーセーブも挙げていたが、そのあとこの #300 で、版をまたいで引き継がれないことを持ち主が了承した。いまは、メモリーセーブは版が変わると使えない（[builtin-games.md](builtin-games.md)）。この読み方は要確認。
- **#446** 内蔵ソフトの古い版のゲーム内セーブは、自動では今の版と 1 つ前の版を残し、それより古い版だけ消す。1 つ前の版はメニューの「古い版のセーブを消す」で人が消す。
  - セーブの形が変わった版は形ごとに最新 1 版を残す。ゲームのセーブに ID は入れない。利用者の ROM・過去の版の一覧に無い ID は消さない。
  - 持ち主:「ユーザが正常に引き継ぎできている、と判断できたら古いのは消すという運用。」アプリが推し量って消す形には戻さない（[dev-notes.md](dev-notes.md) の「試してやめたこと」）。

## 倍速・更新

- **#49** 上の操作列のボタンで ×1→×1.5→×2。一時停止はメニュー。音は速くするが高さは変えない。
  - ROM 切り替え・リセットで ×1 に戻す。通信中は ×1 固定。0.1 秒以上遅れたら音を今に合わせ直す（暴走させない）。
  - 持ち主:「音が高くなるのが不快です。」
- **#50** 新しい版は「新しい版があります（再読み込み）」で知らせ、メニューにバージョンを出す。白黒／カラーは ROM で自動判定、ROM の削除はない。
  - 自動では読み込み直さない。バージョンは「ビルド日時 (コミット)」。起動できなかった ROM も一覧に残る。

## 通信ケーブル

- **#51** 同じ Wi-Fi の iPhone 2 台を WebRTC（QR かコピペで接続、サーバーなし）でつなぎ、進みを合わせながら待つ方式。ROM は送らない。
  - Bluetooth は Web アプリから使えないので使わない。外の STUN/TURN も使わない。つないでいる間は ×1 固定・ロード不可。設計は [link-cable-design.md](link-cable-design.md)。iPhone 2 台で動いた。

## 配信とリポジトリ

- **#97** GitHub Pages で配信し、リポジトリも public にしてよい。手元でビルドして出す。配布は目的ではない。
  - Netlify の無料プランはデプロイのクレジットが足りなかったため。市販 ROM は git にも配信にも入れない。CI は作らない。
  - 持ち主:「別に配布したいわけではない。」
- **#112** 前に使っていた Netlify のサイトは消さずに放っておく（デプロイも削除もしない）。
- **#108** 開発に使う Claude（親のセッション）は、レビューして問題のない PR の squash マージと公開（`cd app && npm ci && npm run deploy`）を、持ち主に聞かずにしてよい（離席中も）。リポジトリやサイトの削除など、ほかの取り消せない操作は含まない。
  - 持ち主:「github pagesになったのでデプロイ制限もありませんしマージも公開もして構いません」
- **#514・#515** 2026-10-31 に、前の公開リポジトリ（`retroboy-snap`）から、このリポジトリ `sny-tanaka/retroboy`（配信 https://sny-tanaka.github.io/retroboy/ ）に移した。前のリポジトリは非公開にして控えとして残す（あとで消してもよい）。セーブは持ち主が新しいアドレスで `.ss1` を読み込んで移す。
  - ソースを別の非公開リポジトリで作るゲームは、その資料とソースをこのリポジトリの履歴から外し、できた物だけをここで配信する（#509）。
  - 文書やコードに残る `retroboy-snap`（IndexedDB の名前・キャッシュの名前など）は、前の名前のまま使っている識別子。変えるとセーブや ROM が読めなくなるので変えない。

## 作業の決まり（テイマーズライフのリポジトリと共通）

- **#55** 開発サーバー（と自動の確かめ）は基本的に無音で動かす。
  - `vite dev` は既定で無音（`?sound=1` で鳴らせる）。`vite preview`・Playwright など本番ビルドの確かめも `?mute=1` で無音。iPhone の本番は鳴る。
  - 持ち主:「開発サーバを基本的に無音で立ち上げてほしい」
- **#234・#280** 並べて動かすセッション（子）は同じ Mac で動くので、重い処理（fuzz・ROM のビルド・`cargo test`・`npm run check`・試算）は 1 つの子につき同時に 1 本、`nice -n 15` を付けて流す。並べる数は CPU を見て決める（6 本まで）。
  - 持ち主:「CPUが張り付いてます。コントロール上手くやってください」
- **#433・#500** PR ごとにいちいち公開しない。同時に頼んでいる作業が全部終わってからまとめて公開する（マージはしてよい）。動いている子が 1 つでもあれば、その子の PR が入るまで公開しない。
  - 持ち主:「いちいち公開しなくていいです。全部終わってからまとめて公開して」「同時に頼んでいるものが全部終わってから公開してください」
- **#372** 内蔵ソフトに不具合が出ても、前の版に戻して公開し直さない。直した版で公開する。
  - 前の版に戻すと、`app/src/storage/builtinGames.ts` の carryOverSave（新しい版にセーブがあれば写さない）で、前にその版で遊んだ古いセーブが読まれてしまう。
- **#424** 持ち主への質問は必ず AskUserQuestion で聞く（チャットの文で問いを並べない）。
  - 持ち主:「私への質問は必ずそうして。」
- PR の題は出す前に仕上げる（WIP のまま squash マージしない）。
